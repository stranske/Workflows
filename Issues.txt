labels: [agent:codex, bug]
body:

This does not add a new provider.

- [x] Update FallbackChainProvider to pass quality_context through to underlying providers that support it.
- [x] Update codex_session_analyzer.analyze_session to always pass quality_context when available, including when using the fallback chain.
- [x] Add regression tests proving confidence capping is applied in the fallback-chain path.

## Acceptance Criteria

- [x] Unit tests demonstrate that quality_context reaches the active provider even when wrapped by FallbackChainProvider.
- [x] Regression tests demonstrate confidence is capped when analysis_text_length is very short and has_work_evidence is true.
- [ ] No existing callers break due to signature changes (CI passes).

3. [LangChain] Structured output + single-repair retry for JSON-returning scripts
labels: [agent:codex, enhancement]
body:
## Why

Several scripts rely on brittle JSON extraction from LLM output. When the model emits preamble text, markdown wrappers, or partial JSON, automation becomes flaky.

## Scope

Add strict structured-output parsing (Pydantic models + validation) and a single repair retry that feeds validation errors back to the model for:
- `scripts/langchain/issue_optimizer.py` (analysis JSON)
- `scripts/langchain/pr_verifier.py` (evaluation JSON)

## Non-Goals

This does not rewrite prompts end-to-end.
This does not introduce multi-retry loops (one repair retry only).

## Tasks

- [ ] Use strict Pydantic validation as the primary parsing path in issue_optimizer (avoid regex JSON extraction as primary).
- [ ] Use strict Pydantic validation as the primary parsing path in pr_verifier (evaluate + compare).
- [ ] Implement a single repair retry that includes schema plus the validation error message when parsing fails.
- [ ] Add tests with malformed outputs (preamble text, markdown fences, trailing commas) and confirm repair produces valid JSON.

## Acceptance Criteria

- [ ] For invalid model output, scripts perform exactly one repair attempt and then either succeed with valid structured output or fail with an explicit parsing error.
- [ ] Tests cover at least three malformed output patterns per script.
- [ ] Existing behavior remains compatible for valid outputs (tests pass).

## Implementation Notes

Primary files:
`scripts/langchain/issue_optimizer.py`
`scripts/langchain/pr_verifier.py`

5. [Security] Add prompt-injection guardrails for issue rewrite + follow-up generation paths
labels: [agent:codex, enhancement]
body:
## Why

Automation steps ingest user-controlled markdown (issues/PR bodies/comments) and can rewrite issues or generate follow-up issues/PRs. A conservative injection guard reduces the risk of instruction smuggling and unintended actions.

## Scope

Add a lightweight prompt-injection detector and wire it into scripts that rewrite issue content or generate follow-up issues. If triggered, fail safe (no rewrite) and clearly signal needs-human.

## Non-Goals

This does not aim for perfect detection.
This does not attempt to block every jailbreak; it targets high-signal patterns.

- [ ] Integrate the guard into `scripts/langchain/issue_formatter.py`, `scripts/langchain/issue_optimizer.py`, and `scripts/langchain/followup_issue_generator.py` (skip LLM call and/or skip applying changes when flagged).
- [ ] Update workflows/templates to apply a safe label/comment when the guard blocks execution (e.g., add needs-human and a short explanation).
- [ ] Add tests with representative injected inputs confirming the guard blocks and outputs clearly signal the block.

## Acceptance Criteria

- [ ] Injected inputs cause a safe block: no issue body rewrite occurs and the workflow signals needs-human with a clear message.
- [ ] Non-injected inputs proceed as before (existing tests pass).
- [ ] The guard is unit-tested with multiple injection patterns and at least one false-positive control.

## Implementation Notes

`scripts/langchain/followup_issue_generator.py`
