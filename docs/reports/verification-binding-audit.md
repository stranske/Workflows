## Contract and method

A request is a successful dispatch of verification work. A terminal verdict is a complete report for the intended source/attempt. Acceptance additionally requires current source/merge identity, applicable CI, review/merge gates and the owning source disposition. A label, parser truth value, task checkbox or green workflow cannot substitute for these boundaries.

Read README Verification Pipeline, WORKFLOW_GUIDE, ci/WORKFLOWS, INTEGRATION_GUIDE, ops/CONSUMER_REPO_MAINTENANCE, keepalive/Agents and GoalsAndPlumbing. The maintenance contract requires merged-source checks and trusted helpers; the README independently requires current-head checks, review resolution and seven minutes.

Reproduce the inventory from the recorded revision with:

```sh
rg -n 'verify:evaluate|verdict|is_terminal_artifact|artifact_from_verification_text' .github/workflows .github/scripts scripts/langchain templates/consumer-repo/.github/workflows -g '*.py' -g '*.yml' -g '*.js' -g '!**/__tests__/**'
```

Scope excludes tests as transition producers, archives, docs, local lane/runtime implementations, backplane deferral and repositories outside the accepted fleet. Test files are read as evidence, not counted as runtime consumers. Pure formatting, health checks, dispatch-only wrappers and historical harvesting remain in the inventory so their exclusions from acceptance authority are reviewable. Search terms are a bounded lexical inventory, not proof that every synonymous transition in the repository has been discovered.

## Reproductions and missing assertions

1. **Historical PASS reused by an incomplete newest report**, source #3966. On this revision, passing `## PR Verification Report\nVerdict: PASS\n\n## PR Verification Report\nContext extraction failed before any provider returned.` to `artifact_from_verification_text`, then `is_terminal_artifact`, returns a PASS artifact and `True`. A recognized `Schema repair pending` marker does block; absence of that exact marker does not establish a current verdict. Add a regression to `tests/scripts/test_verifier_config.py` that requires the latest report itself to carry the terminal verdict; include latest missing-verdict, interrupted, stale PASS and valid latest terminal cases. Exercise both workflow consumers with source PR/attempt mismatches. Do not change the old report's historical verdict to make this pass.
2. **Issue-only request label treated as done**, source #3967. Running `determineNextStep({issueState:'closed',hasVerify:true,linkedPr:null})` returns `closed-verified` and `done`. Add a case to `.github/scripts/__tests__/auto-pilot-transitions.test.js` requiring pending/requested handoff until a merged source PR is established; a provider PASS need not be required merely to report request dispatch.
3. **Skipped settlement / unbound sink**, source #3969 and existing PR #4124. Current main tests some terminal CI behavior; the open PR must supply the expanded skipped/missing-settlement and source-bound sink negatives. Inspect actual current-head execution and artifacts before considering that fix shipped. This audit does not duplicate its code or claim deployed verification success.

The root and template auto-pilot rows share source #3967. Both follow-up workflow rows and the terminal parser share source #3966. Sink/serializer review remains within source #3969. No additional independently confirmed instance beyond these owners was established, so no duplicate follow-up issue was filed. New findings, if later established, require the separate publication approval stated in source #3968; audit publication is not approval to file them.
