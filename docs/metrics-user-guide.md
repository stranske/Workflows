# Metrics User Guide

Use this guide to understand the weekly metrics dashboard output generated by
`scripts/metrics_dashboard_generator.py`.

## Dashboard layout

The dashboard is a single markdown file with these sections:

- **Header:** `# Weekly Metrics Dashboard` followed by generation timestamp,
  total entries, and parse errors. Use this block to confirm the dashboard is
  fresh and that no data failed to parse.
- **Org Summary:** Aggregated stats across all repos for each metric field.
  Columns:
  - `Mean`, `P50`, `P90`, `P99`: summary distribution percentiles.
  - `Trend`: sparkline showing the metric's recent direction.
  - `Status`: threshold evaluation (OK/WARN/FAIL) when thresholds are configured.
- **Per-Repo Summary:** A repo overview table with entry counts, number of
  metric fields tracked, and the most recent update per repo.
- **Repo Details:** One section per repo. Each repo block includes entry count
  and a metrics table that mirrors the Org Summary columns for that repo only.

## Reading key fields

- **Total entries:** Total NDJSON rows parsed after aggregation.
- **Parse errors:** Rows that could not be parsed as JSON.
- **Entries (per repo):** Number of metrics rows for that repo. A low count can
  indicate missing runs or a stalled collector.
- **Status:** Based on thresholds in the optional config. If no thresholds are
  set, the value is `n/a`.

## Troubleshooting

### Missing data

Symptoms: Repo is absent from the dashboard, or entry counts are zero.

Checks:
- Confirm the per-repo NDJSON exists under the metrics directory (default
  `repo-metrics/owner__repo.ndjson`).
- Re-run aggregation with the expected `--repos` list.
- Ensure the source workflow emits numeric fields and timestamps; entries
  without numeric fields are skipped in tables.

### Stale metrics

Symptoms: `Last update` timestamps are old or the `Generated` time is current
but metrics are not.

Checks:
- Verify the metrics collection job is still running on schedule.
- Inspect the summary JSON (`repo-metrics-summary.json`) for recent timestamps.
- Confirm the dashboard generator is reading the newest combined NDJSON file.

### Badge failures

Symptoms: README badges show `invalid`, `unknown`, or stale data.

Checks:
- Rebuild badge payloads with `scripts/generate_metrics_badges.py` using the
  latest summary JSON.
- Ensure the badge endpoint JSON files are published at the configured URL.
- Re-run `scripts/update_readme_badges.py` so README badge links point at the
  correct endpoint base.
